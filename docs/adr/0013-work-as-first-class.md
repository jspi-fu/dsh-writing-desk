# 作品是第一位实体:素材可复用,发布稿冻结

Status: accepted(2026-11-20 与用户逐项定案;分阶段实现。部分取代 0006 的「成稿产物挂在灵感上」、0007 的「内容页四列稿子看板」与 0011 的「胶囊成员逐个同步排期/状态/发布」。2026-11-20 修订:删除自动成稿与自动投递——DSH 不允许替用户回车,排期只保留到期提醒)

## 背景

现在的 `production` 挂在灵感或胶囊成员身上,带来四个无法回避的问题:

- 一篇稿只能属于一个灵感/胶囊。灵感删了稿也没了;同一份素材想写第二篇,只能复制一份灵感,历史关系随之消失。
- 内容页按「灵感 / 成稿 / 待发布 / 已发布」四列把素材和稿混在同一批 `items` 里;没有独立的作品实体,也就没有作品页、发布状态、蓝点历史。
- 一篇稿的「AI 最后一版」只能靠 `snapshots` / `aiArticle` 区分,人工改过哪里靠 pen 徽章猜;用户已经明确不要这套状态管理。
- 胶囊被定义成「成稿产物落在某个成员身上」,与用户对胶囊的理解冲突:「胶囊就是包含一整个完整稿件的所有素材」;成员不能单独成稿、单独排期。

用户同时明确:灵感/胶囊成稿后不删除;按会话归档的思路给它们专门分类,隐藏/显示/删除权交给用户;已用素材点开仍进灵感编辑;同一素材可以复用成多稿;卡片用蓝点标记「已用于成稿」,点开能看到成稿历史。

## 决策

| 事项 | 决策 |
| --- | --- |
| 作品是第一位实体 | 新增 `state.works`。一篇稿=一个 `Work`;素材(灵感与胶囊)只作为它的来源。旧 `item.production` 与胶囊成员上的 `production` 全部迁出。 |
| 作品字段 | `Work { id, sourceItemIds[], sourceCapsuleIds[], sourceSnapshot[], current, published?, publication, sessionIds[], createdAt, updatedAt, archivedAt? }`。`current` 是当前稿:`{ title, coverText, article, cover, images, intent, review, rev }`;`published` 是发布时冻结的只读副本,字段同 `current` 再加 `publishedAt`;`publication` 是发布记录:`{ status: 'draft' \| 'submitted' \| 'published', submittedAt?, publishedAt?, dispatches? }`。 |
| 素材与作品分离 | 灵感/胶囊上不再有 `production`;素材只保留原始输入字段(标题、正文、标签、封面、文件、排期主体)。`sentToSession` 与「审读中」相位随 0006 的实现退场;作品创建即表示「已开始成稿」。 |
| 一次成稿=一个作品 | 点「成稿」立即创建 `Work`(草稿,标题取来源的显示标题,`current` 为空);创作会话写回这份作品。同一素材再次点成稿=再建一个 `Work`,旧作品保留;两张作品互不影响。胶囊一次成稿产生一个 `Work`,不是每个成员各一份。 |
| 素材复用 | 一个素材可被任意多个 `Work` 引用;`sourceItemIds`/`sourceCapsuleIds` 只是指针,不复制正文。作品页、成稿历史、风格学习都按这些指针工作。 |
| 已用素材 | 不再存 `used` 布尔值;只要任一 `Work` 引用了该素材,它就派生为「已用」。已用素材默认从灵感墙主列表与待排期托盘收起,与标签栏同级进入「已用」分组;显示/隐藏与「全部删除已用」由分组右侧 `ellipsis-horizontal` 菜单管理。删除只删素材,不删作品。 |
| 删除素材 | 删除灵感或解散胶囊只影响素材本身;作品保留 `sourceSnapshot`(至少 id、标题、类型、胶囊名)供历史与蓝点展示。作品正文不因素材删除而丢失;作品页的「重写一篇」仍可从作品自己的当前稿继续。 |
| 删除作品 | 只删 `Work`;来源素材不动,自动回到未用状态(若没有别的作品引用)。空草稿可以在作品页直接删。 |
| 胶囊 | 胶囊仍是命名素材集合与一次成稿的输入单位;成员不能单独成稿、不能单独排期。胶囊的排期与提醒设置以整张胶囊为主体,不再逐成员同步字段。成员可以继续独立编辑自己的原始字段(ADR 0011 的收下/拖拽/合并规则不变)。 |
| 排期主体 | 排期属于「一个待成稿的素材主体」:单条灵感或整张胶囊。当前实现沿用阶段一的扁平字段:`scheduledAt`(唯一时间源)、`reminder`、`remindedAt`、`platform`;不引入 `schedule` 对象。胶囊成员的旧排期合并为胶囊主体的一条。作品本身的发布排期不在本期(留待后续 ADR)。 |
| 排期语义 | `scheduledAt` 是「到点提醒」的触发时刻,不是成稿时刻,也不是发布时刻。到点只弹应用内提醒,由用户自己决定何时点成稿;系统不替用户建作品、不替用户投递或发布(DSH 的创作会话只能预填,不能替用户回车,自动成稿没有实际意义)。成稿一旦落库(手动),主体的排期即消费掉,避免同一排期反复提醒。 |
| 发布状态 | `publication.status` 只有 `draft / submitted / published`。「已投递」= 至少一条平台回执成功,机器记录;「已发布」= 用户手动确认。投递不写 `published`,发布必须人工确认(0006/0009/0010 的红线不变)。发布时把 `current` 冻结成 `published`;之后再改 `current` 只显示「有未发布改动」,不改 `published`。 |
| 发布副本 | 只有一份 `published`,不存版本列表。发布后再次发布会用当时 `current` 覆盖 `published` 并记录新的 `publishedAt`;旧发布文本不保留。 |
| 成稿历史 | 素材卡右上/角上的蓝点表示「该素材被至少一个作品引用」;点蓝点(或卡片菜单「成稿历史」)列出引用它的 `Work` 的标题与创建时间;点历史项打开对应作品编辑器。胶囊的蓝点按整张胶囊的被引用情况计算。 |
| 内容栏目 | 内容页默认「我的作品」画廊;保留「流程」看板切换,两种视图共享同一批 `Work`。画廊与看板都不再直接展示灵感;灵感墙仍是素材的唯一主入口。 |
| 关系 | 0006 的「production 挂 item、写回快照、校样浮层、内容页四列稿子看板」由本 ADR 取代;0006 的「写发生在会话、插件不做模型调用、发布由用户确认」继续有效。0011 的「胶囊整张同步排期/状态/发布」由「排期以主体为单位、状态属于作品」取代;0011 的胶囊折叠、拖拽、收下规则继续有效。 |

## 不做

- 不做版本历史、不做字段级快照、不做「人工改动」标识(见 0014)。
- 不做自动发布,也不做自动成稿/自动投递:排期到点只提醒;投递与发布都必须由用户在作品编辑器里手动触发,是否对外可见仍由用户确认。
- 不做作品级发布排期;本期排期只服务「到点提醒」。
- 不把素材正文复制进作品;来源只存指针与最小 `sourceSnapshot`。
- 不做多设备/多窗口同步;作品数据仍落在本地 `state.json`。

## 交互流程

1. 灵感墙上点一张灵感卡的「成稿」:立即出现一篇空作品(标题取灵感标题),打开作品编辑器;灵感卡出现蓝点,进入「已用」分组。
2. 同一张灵感再点一次成稿:再建一篇作品;蓝点历史里现在有两篇,分别可打开。
3. 胶囊点成稿:只建一篇作品,来源是整张胶囊;成员不各自产生作品。
4. 作品编辑器里写完、改完:当前稿自动保存;点发布并确认,`published` 冻结,作品页显示「已发布」。若先投递,显示「已投递」,发布仍需人工确认。
5. 删除一张已用素材:灵感从墙上消失;作品打开仍完整,蓝点历史仍能显示来源标题(来自 `sourceSnapshot`)。
6. 排一张灵感到明天 09:00,默认开提醒:到点应用内提醒;点「去处理」可以自己成稿,排期消费,不再提醒。
7. 排一张胶囊到下周一 09:00:到点只提醒一次(整张胶囊一条);没有自动成稿、没有自动投递,何时成稿由用户决定。
8. 内容页切「流程」:同一批作品按状态分列,不出现灵感素材;点卡片仍进同一个作品编辑器。

## 验收场景

1. `state.works` 存在;旧数据迁移后 `items`/`capsules` 上不再有 `production`,每份旧成稿对应一个 `Work`,标题/正文/封面/发布记录不丢。
2. 同一灵感连续成稿两次得到两个不同 `Work`,互不覆盖;删除灵感后两篇作品仍可打开,蓝点历史仍显示来源标题。
3. 已用素材默认不在灵感墙主列表与托盘;菜单可显示/隐藏;全部删除已用只删素材,作品数不变。
4. 胶囊成员没有独立成稿/排期入口;胶囊的排期创建一篇作品,成员不各建一篇。
5. 排期到点只提醒一次;手动成稿后清掉排期;错过提醒下次打开只补一次,可手动关闭;不存在到点自动建作品或自动投递。
6. 发布确认后 `published` 冻结;改 `current` 后作品页仍显示已发布,并标「有未发布改动」;再发布才覆盖 `published`。
7. `npm test` 全绿;构建后四个页面照常挂载。

## 后果

- `src/state.js` 新增 `works` 与作品 reducer;`src/ops.js` 的 `update_production` / `publish_item` / `schedule_item` 迁到作品/排期主体;所有 `item.production` 读取点(内容页、卡片、胶囊、会话工具)改读 `Work`。
- `src/produce-input.js` 不再只取 `targetId: sourceIds[0]`;作品创建改为记录整组来源。
- 预设工具 `writing_desk_read` 仍读素材;`writing_desk_write` 改为写 `Work`;作品创建仍走 `create_work`(手动成稿与预设工具),到点没有自动创建路径。
- 旧 `production.snapshots`、`aiArticle`、`savedHashes` 等字段在迁移时丢弃;不做兼容读取。
- 作品页、作品编辑器、已用分组、蓝点历史都需要新的客户端组件与文案。
- 迁移是一次性、可撤销的整批操作;迁移后旧版本插件读不到作品内容,回退需要恢复迁移前的 `state.json` 备份。

## 回滚

迁移前的 `state.json` 由 host 自动备份;回退版本时恢复备份即可。作品字段对旧版本是未知字段,读取会被忽略,但旧版本看不到作品正文,不能作为降级方案长期使用。

## 阶段一过渡备注(已落地)

作品模型落地前,排期设置先以扁平字段与 `scheduledAt` 同处一条素材卡,不引入本文的 `schedule` 对象——只改这一处口径的收益抵不上同时改 47 处 `scheduledAt` 读取点与 56 处测试的成本:

- 素材上新增 `reminder`(boolean,缺省视为开)与 `remindedAt`(date);`scheduledAt` 仍是唯一时间源。自动成稿/自动投递的旧字段(`autoProduce`/`autoDispatch`)已删除,不再由 ops 写入。
- 胶囊不新增胶囊级字段,沿用 `capsuleRows(state, item)` 把这些字段镜像到全部成员,与既有的整张排期/状态同步同一机制。
- 新增操作 `ack_reminder`:写 `remindedAt`,无回执、不进撤销栈;改期(`schedule`)与取消排期(`unschedule`)清掉它,因为回执只属于「这一次」排期。
- 「到了点该提醒」只有一处判断:`src/state.js` 的 `reminderDue(item, now)`,Host 与 Client 共用。
- 阶段二只把作品模型落地;排期形状保持不变(仍读 `scheduledAt`),也没有迁成 `schedule` 对象。`reminderDue` 继续读素材上的 `scheduledAt`/`remindedAt`/`reminder`,界面与文案不变。
