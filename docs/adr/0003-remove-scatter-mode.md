# 撤销散落模式，只留灵感流

Status: accepted（2026-11-17）

## 背景

首页原本有两种展示方式：散落画布（自由坐标、可平移缩放、卡片可拖到任意位置）和按时间排的信息流。两种模式各自维护一套定位、拖拽与命中逻辑：画布有相机、世界层、节点动画、缩放工具条，`src/ops.js` 还为每条灵感与每个胶囊存了 `pos` 坐标。

实际使用里，散落画布几乎没有被用来「摆」，反而带来三处持续成本：同一个灵感在两套布局里出现，判定与样式要写两遍；胶囊的九宫格形状和画布障碍矩形要跟着坐标走；坐标写进数据后还要迁移、还要为解散补落点。

## 决策

只保留按时间排的灵感流。散落画布连同它的全部机制一起删除，不保留开关：

- 首页固定是灵感流：首屏那句话 + 胶囊资料架 + 卡片墙，全部按时间（相关推荐命中时按相关度提前）。
- 删除相机、世界层、节点、缩放工具条、拖拽摆位、障碍布局与相关推荐的「左右排点」。
- 数据层删除坐标：`items[].pos`、`capsules[].pos` 不再写入，读取时顺手清掉；`add_capsule` / `update_capsule` / `update_item` 不再接受 `pos`。
- 拖拽仍然保留，但都落在同一个面上：拖卡到卡上合成胶囊、拖卡到胶囊上加入、拖胶囊里的卡到别的胶囊或空白处移出、浮层内拖动排序。

## 后果

- 少了一整个视图：`client/canvas.jsx` 从约 1000 行降到 350 行，`client/layout.js` 删除，`relatedLayout`、`seeded` 等只服务散落的纯函数一并删除。
- 灵感不再有「我上次把它摆在哪儿」的价值，时间顺序成为唯一顺序；要找某一条靠标签与相关推荐。
- 胶囊的交互面统一：关闭态在资料架上，浮层居中放大，成员移出即回到灵感流。
- 历史数据里的坐标字段读一次就清掉，不影响其它字段。

## 代码影响

- `client/canvas.jsx`：只保留 `Feed` 与 `HomeView`，去掉 `useCamera`、`Scatter`、`Node`、展示方式切换。
- `client/desk.js`：删 `mode` 状态。
- `client/layout.js`：删除（散落布局与卡片尺寸估算）。
- `client/related.js`：删 `relatedLayout`。
- `client/capsule.jsx`：移出成员不再换算画布坐标。
- `src/ops.js` / `src/seed.js`：删 `pos` 字段、`capsuleCenter`、铺回网格的落点计算；迁移时清理旧坐标。
- `client/styles.css`：删画布、世界、节点、缩放工具条、连线等规则。
