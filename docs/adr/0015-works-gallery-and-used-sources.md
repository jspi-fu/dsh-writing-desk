# 内容栏目改为「我的作品」画廊,已用素材收进同级分组

Status: accepted(2026-11-20 与用户逐项定案;实现分阶段落地。取代 0007 的「内容页四列稿子看板」作为默认视图)

## 背景

0007 把内容页做成四列看板(灵感 / 成稿 / 待发布 / 已发布),因为当时稿子就是 `item`,素材与作品是同一批数据。0013 把作品拆成独立实体后,这个看板同时混了两类东西:

- 「灵感」列其实是素材,不是作品;它应该留在灵感墙,而不是内容栏目。
- 「成稿 / 待发布 / 已发布」列是作品状态,但一张卡片点开是校样浮层,没有封面画廊,也看不出「这篇发没发、改没改」。
- 用户要的是「我的作品」:默认看到自己写过的稿,显示是否发布,点开就能编辑并即时预览,像 Obsidian 一样左写右看、自动保存。
- 同一批素材会被多篇作品引用,素材本身需要一个「已用」归档处;否则灵感墙会越堆越乱,删素材又会让人担心稿子一起没了。

## 决策

| 事项 | 决策 |
| --- | --- |
| 内容栏目默认视图 | 「我的作品」画廊。顶部保留分段切换「我的作品 / 流程」;默认落在画廊。灵感墙独立,不在内容栏目里重复素材。 |
| 画廊卡片 | 两列网格(窄面板)或 auto-fill;每张:16:9 封面(无封面用首字色纸)、两行标题、状态徽章(草稿 / 已投递 / 已发布)、来源数(例如「3 个素材 / 1 张胶囊」)、更新于。整卡点击打开作品编辑器;不设单独预览弹层。 |
| 状态 | 只显示三种:草稿(灰)、已投递(蓝)、已发布(绿)。没有「待发布」「审读中」「人工修改中」。发布状态以用户确认为准;投递只显示已投递。 |
| 筛选 | 顶部分段或 chip:全部 / 草稿 / 已投递 / 已发布;搜索框过滤标题与来源标题;排序默认最近更新,可切最近创建。筛选状态不写回 state。 |
| 流程看板 | 「流程」是同一批 `Work` 的第二种看法:三列草稿 / 已投递 / 已发布,按 `publication.status` 分列;卡片可点开编辑器,不提供拖拽改状态(投递与发布都不是拖出来的)。单篇内部的创作阶段(选题/意图/结构/初稿/审稿/配图/人工编辑/发布)放在作品编辑器的流程侧栏,不占看板列。 |
| 作品编辑器 | 全屏浮层,不引入路由。顶栏:返回、标题、保存状态、状态徽章、发布按钮、更多菜单(删除/学习写法/复制正文/导出发布包);主体左编辑右实时 Markdown 预览,可切纯编辑/纯预览/发布稿;平台宽度切换微信 578 / 小红书 375 / 知乎 700,按真实 CSS 重排,不做 transform 缩放。 |
| 实时预览 | 正文编辑区是 Markdown 源文;右侧用现有 `renderMarkdown` 即时渲染,不经过 iframe 缩放。微信预览的排版 HTML 另按需生成(0016),不阻塞普通预览。 |
| 发布稿 | 编辑器顶部可切「发布稿」只读视图;没有发布稿时禁用。发布后 `published` 冻结;`current` 有改动时画廊卡与编辑器显示「有未发布改动」,不存 diff。 |
| 删除作品 | 作品卡菜单与编辑器更多菜单可删除;空草稿可直接删;删除后作品从画廊/看板消失,来源素材回到未用状态(若没有其他作品引用)。删除可撤销(toast 带撤销)。 |
| 已用素材 | 灵感墙底部与标签栏同级增加「已用」分组;默认收起,主列表不显示已用素材。分组右侧 `ellipsis-horizontal` 菜单:「显示已用素材 / 隐藏已用素材」「全部删除已用素材」。开关只影响显示,不改数据;删除全部只删素材,不删作品,带确认与撤销。 |
| 已用标记 | 被至少一个 `Work` 引用的灵感/胶囊卡显示蓝色小点(不抢状态色);点蓝点打开「成稿历史」小浮层,列出作品标题与创建时间,点条目打开对应作品。蓝点不改变整卡点击行为:点卡身仍进灵感编辑/胶囊浮层。 |
| 已用素材点开 | 已用灵感仍进统一灵感编辑对话框,可改标题/正文/标签/封面;已用胶囊仍进胶囊浮层。编辑不会改作品正文;作品只是引用指针。 |
| 删除已用素材 | 删除灵感/解散胶囊只影响素材;作品保留 `sourceSnapshot`;蓝点历史仍显示来源标题。删除有确认,可撤销。 |
| 空状态 | 画廊无作品:一句「还没有作品。从灵感墙选一张卡,点成稿开始。」+ 去灵感墙按钮;流程空列显示轻提示;已用分组为空时不显示。 |
| 视觉边界 | 画廊是白纸卡与柔和封面,不使用瑞士风直角/等宽/1px 边框;状态色只做小徽章,不做整卡底色;不使用 iframe + `transform: scale`(No-Scale Rule)。 |
| 与灵感墙的关系 | 两个页面共享同一份数据,但不共享卡片形态:灵感墙是素材卡与胶囊相册卡;内容栏目是作品卡与作品编辑器。作品不提供「加入胶囊」「拖回托盘」等素材操作。 |

## 不做

- 不做作品拖拽排序、不做自定义封面裁切、不做画布式自由布局。
- 不做发布排期、不做定时发布;发布仍是人工确认。
- 不做作品版本列表、不做 diff 视图(0014)。
- 不做独立作品详情路由;全屏浮层即可,刷新后回到内容页。
- 不在画廊里直接编辑正文;编辑只发生在作品编辑器。

## 交互流程

1. 进入内容页:默认「我的作品」;有作品时按最近更新排列,卡片显示状态;点卡进入作品编辑器。
2. 作品编辑器改标题/正文:右侧预览即时变;约 700ms 后顶栏显示已保存;返回画廊,卡片标题与更新时同步。
3. 点发布:确认后状态变已发布,`published` 冻结;继续改稿,画廊显示「有未发布改动」;切「发布稿」能看到发出去的那版。
4. 切「流程」:三列按状态展示同一批作品;点卡仍进同一个编辑器;没有拖拽改状态。
5. 灵感墙上点一张已用素材的蓝点:浮层列出两篇作品;点第二篇打开其编辑器;点卡身仍进灵感编辑。
6. 灵感墙菜单「显示已用素材」:已用卡以低饱和分组出现;再点「全部删除已用素材」并确认:素材消失,作品仍在;toast 可撤销。
7. 删除一篇作品:画廊/看板移除;来源素材若不再被引用,回到未用;可撤销。

## 验收场景

1. 内容页默认是「我的作品」,不出现灵感列;切「流程」后只出现作品卡,不出现素材。
2. 画廊卡显示封面、标题、状态、来源数、更新时间;点卡打开全屏编辑器。
3. 编辑器左写右看,Markdown 即时预览;切换平台宽度按真实字号重排,不缩放;刷新页面内容不丢。
4. 发布后画廊状态变已发布;改稿后出现「有未发布改动」;发布稿视图只读且仍是旧内容。
5. 已用素材默认不在灵感墙主列表;菜单可显示/隐藏;全部删除只删素材,作品数与蓝点历史不变(标题来自快照)。
6. 蓝点历史列出引用该素材的全部作品;点历史项打开对应作品;点卡身仍进灵感编辑。
7. 删除作品不影响素材;删除空草稿不弹多余确认;删除操作可撤销。
8. `npm test` 全绿;构建后内容页、灵感墙、排期页、风格页照常挂载。

## 后果

- 新增 `client/content.jsx`(作品画廊/流程/已用分组,原计划的 `client/works.jsx` 合并进来)与 `client/work-editor.jsx`(全屏编辑器,原计划的 `client/work.jsx`);`client/card.jsx` 加蓝点与历史入口;`client/proof.jsx` 下线。
- `client/styles.css` 新增作品卡、画廊、编辑器、发布稿、蓝点与历史浮层样式;追加在文件末尾,避免卷入历史重复段。
- `client/en/*` 新增作品/状态/已用/历史/发布稿词条;`GLOSSARY.md` 与 `DESIGN.md` 同步。
- 内容页的 `phaseOf`、`PhaseBadge`、`IntakeBar`、四列看板与校样浮层逻辑删除。
- 已用分组默认收起是主动取舍:用户需要多点一次才能复用旧素材,换来主列表干净;复用入口仍在蓝点历史与「显示已用」。

## 回滚

客户端组件可回退提交;数据层回退需恢复迁移前 `state.json`(0013 已说明)。`works` 数据对旧版本不可见,旧版本内容页不会显示作品。

## 修订(2026-11-21):作品页卷首与按容器响应

视觉与断点以 `DESIGN.md`「作品卡与作品页」为准;本 ADR 的决策表保留原始定案。实现上的偏差:

- 画廊不再用两列固定网格,也不再有状态徽章与状态筛选 chip:卷首是日期、带数字的大话与 48px 大搜索,下面目录尺 + `auto-fill` 网格;卡片用序号、衬线标题、状态点、日期与来源行。
- 搜索只匹配作品标题与来源标题,不按状态过滤;排序固定最近更新。
- 作品页改为 inline-size 容器,按自身宽度(840/560/420)响应,不再依赖视口断点;空态纸板 ≤840 缩小、≤420 隐藏并换成「01 —— 第一篇」标记。
- 胶囊浮层宽度 ≤820 时头部动作只留图标、≤660 时内部滚动并把翻页移到底部;成员始终两列,不整体缩放(ADR 0004 2026-11-21 修订)。
